# 濃紺と淡い金のアクセント比較（2026-11-10）

## 何を整理したか

前案では、暗い面・情報の明度・種類の記号は整理した一方、ブランド色と操作を促す色の役割分担が不十分だった。
利用者の「黄色などのアクセント」「デザイン原則」の質問に応じ、配色を役割から定義し直した比較案。

| 原則 | 適用 |
|---|---|
| 図と地 | 濃紺は情報を置く面。本文・ロゴ・グラフは青白く読ませる |
| 序列 | 金は主操作と現在地。塗りは送信などの主ボタン、タブは文字と下線 |
| 一貫した意味 | 情報は青、警告は橙、エラーは赤。通常のデータの点を金にしない |
| 反復・近接・整列 | 既存の文字階層・操作寸法・8/16/24px の余白を保つ |
| 可読性と識別 | 下線・文言・○●⊙を併用し、色だけで状態を伝えない |

色だけに依存しない根拠は [W3C Use of Color](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)、
通常文字の明暗差の基準は [W3C Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)。
配色自体は今回のデザイン判断であり、この組み合わせが唯一の解であるとは主張しない。

## 配色

- 金: `#ebc86e`。hover は `#f5d991`、薄い選択面は `#342f20`。
- ブランドの青白: `#b7ccff`。ロゴの形と色相を維持する。
- 面・グラフ: 元の `night.css` を継承する。
- 金文字/暗面は 10.48:1、金ボタンの文字/塗りは 10.13:1、金文字/選択面は 8.27:1。
  指定 RGB の相対輝度から計算した値で、画面全体の適合認証ではない。
