# 語の組ごとに、閉じた集合から関係を 1 つ選ぶ

状態: 決定（2026-11-18）。実装 = PR 14c。設計の経緯は AI for Science 側
`ui-redesign-2026-10-19/design.md` §23（段 3「関係を選ぶ」・段 4「確かめる」）。

関連: [`knowledge-copy.md`](knowledge-copy.md)（取り込み元の知識を写す・知識の束）/
[`relations-for-experiments.md`](relations-for-experiments.md)（関係の集合・役割の札・問いの型）/
[`ai-roles-make-answer.md`](ai-roles-make-answer.md)（作る AI）。

## 背景

取り込み元の知見を全部写しても（14b）、知識グラフに出るのは語の点だけで、線に意味が無い。
知見の文は「この手法でこの材料を作った」「この材料のこの物性はこうだった」と言っているので、
**同じ知見に出る語の組**ごとに文を読めば、関係が言える。ただし、数百組を 1 回の呼び出しで
読ませると弱いモデルでは形が崩れる。1 回の仕事を「1 組・閉じた集合から 1 つ」に保つ。

## 決定

### 1. 仕事の分け方

| 段 | 誰が | 中身 |
|---|---|---|
| 組を作る | 機械 | 写しの「語 ↔ 知見」から、同じ知見に出る語の組。組ごとに知見を最大 8 件（確認済みを先に） |
| 関係を選ぶ | AI（作る AI） | 2 語の名前・種別・役割と、番号つきの知見の文を見て、関係を 1 つ選ぶか「言えない」。返すのは 関係・主語がどちらか・根拠の番号・理由 1 行 |
| 確かめる | 機械 | 関係が集合にあるか／根拠がその組の知見か／種別と役割が合うか／自分自身でないか／「一種」「一部」が輪にならないか／前に「違う」とされていないか |
| 付ける | 機械 | 文脈の語・確からしさ・確認の状態の内訳 |
| 置く | 機械 | 取り込み元ごとの台帳 |

- AI に渡すのは語の名前と知見の題だけ。**id も IRI も渡さない**（根拠は番号で返させ、機械が知見の id に写す）。
- 選べる関係は下書きの名前 11 個（`quantity` 以外）と `none`。集合は
  [`relations-for-experiments.md`](relations-for-experiments.md) のもの。
- 関係を言うなら根拠 1〜3 件が必須。「言えない」を選ぶ場面をプロンプトに書く（一緒に出るだけ・比べているだけ・
  集合に無い関係・文でなく一般知識に頼るとき）。「同じもの」は、文が同じだと言っているときだけ。

### 2. 機械が付けるもの

| もの | 規則 |
|---|---|
| 文脈の語 | 根拠の知見の半数以上に出る、両端以外の語（最大 3）。2 語の線で表せない「第三の語」を、関係を増やさずに持つ |
| 確からしさ | 根拠の知見が**全部**「見込み」のときだけ `tentative`。「見込み」＝束の `epistemic_status` が `speculation`、または `modal_qualifier` が `possibly`／`rarely` |
| 確認の内訳 | 根拠の知見の `review_state`（`verified`／`candidate`）の件数 |

「見込み」の語彙は知識の束の約束（[`knowledge-copy.md`](knowledge-copy.md)）で、取り込み元の名前では分岐しない。

### 3. 置き場所 — 取り込み元ごとの台帳

`<registry>/vocab-shared/knowledge/<取り込み元>.json`。組ごとに 1 件（`relation`／`none`／`dropped`／`failed`）。

- 話の下書き（`themes/<id>/draft.json`）には入れない。話の下書きは、話に結び付いた承認・上限（概念 120・関係 400）・
  「問いにつながらない概念は作らない」の門を前提にしている。持ち主が取り込み元で、数百本あり、読み直しで差し替わるものを
  載せると、例外が各所に要る。
- 「言えない」の組も残す（候補。既定では見せない）。検査で落ちた組は理由つきで残す。
- **冪等**: 組の指紋 ＝ AI への入力そのもの（2 語の名前・種別・役割と、選んだ知見の id と題）の hash。同じなら聞き直さない。
  知見が増えた・語の役割を直した組だけが聞き直しになる。
- 確認済み（`confirmed`）の組は読み直しで上書きせず、輪の検査でも落とさない。「違う」とされた 3 つ組（`rejected`）は
  次も出さない。写しから消えた組でも、この 2 つのどちらかがあれば台帳に残す。
  この 2 つを書く口は 14e だが、台帳の欄と尊重する規則は今入れる。
- 聞き直しが失敗したとき、前の関係は消さない（次に走らせたときにまた聞く）。
- 壊れた・版の違う台帳は、上書きせずに退避する。

### 4. 取り込み元が知っている関係（題から来た「材料 の 物性」）

写しの `term_relations` は AI を通さず、同じ検査を通して台帳の `origin` に置く。ただし**鵜呑みにしない**:
その 2 語が同じ知見に出ていて AI が文を読んだ組については、AI の判定と突き合わせ、行に印を付ける。

| 印 | 意味 | 扱い |
|---|---|---|
| `agrees` | AI も同じ関係・同じ向きを選んだ | AI の関係（根拠の知見つき）と同じ 1 本として数える |
| `disputes` | AI は文を読んで「言えない」か、別の関係を選んだ | 候補に回す（既定では見せない） |
| `unseen` | 2 語が同じ知見に出ていない（AI は読んでいない） | 取り込み元の言い分として、未確認のまま出す |

取り込み元の言い分で AI の関係を消さない: 「一種」「一部」の輪の検査は AI の関係どうしで行い、
AI の関係と輪になる取り込み元の行のほうを `disputes` にする。

理由: 本物のデータで、題から来た 83 本のうち AI が読めた 43 本の半分（21 本）が食い違った。題を「X の Y」で割ると、
Y が物性でないもの（添加・条件・手法）も「物性」になるため。割り方を良くするのは取り込み元の仕事で、
Asterism は「文が言っているか」だけを見る。

### 5. 走らせる口・読む口

| 口 | 中身 |
|---|---|
| `POST /api/knowledge-copies/{source}/relations` | ジョブを始める。聞くのは台帳に無い組・指紋が変わった組・失敗した組だけ。同時に 4 本。10 件ごとに台帳を保存し、取り消し・時間切れ・途中の失敗でも、済んだ分を仕上げて保存してから終わる。最初の 8 件が全部失敗なら（鍵が切れているなど）残りを聞かずに打ち切る |
| `GET /api/knowledge-copies/{source}/relations` | 台帳を、名前・文・根拠の知見つきで読む |

どちらも書き込みの認証（未確認の知見の題を返すため）。MCP には出さない（外の AI に出すのは確認済みだけ）。

### 6. 確認・「違う」・人が付ける（PR 14e-1）

台帳に「人が確認した」と書く口。ストア（用語・確定した関係・MCP）に置くのは次の 14e-1b で、台帳の
`confirmed` を冪等に写す形にするので、この PR の確認は後から全部載る。5 つの純関数（`pair_relations.py`）は
どれも `(新しい台帳, {changed, skipped})` を返し、入力を変えず、何度かけても同じ結果になる。

| 関数 | 中身 | skipped の理由 |
|---|---|---|
| `confirm` | 見せている関係に `confirmed = {rel, from, to, at, by: "user", evidence}` | `unknown`・`already_confirmed`・`pair_has_relation` |
| `unconfirm` | `confirmed` を消す（未確認に戻る） | `unknown`・`not_confirmed` |
| `reject` | その 3 つ組を `rejected` に足し、`dropped`（理由 `rejected`）にする。`confirmed` は消す | `unknown`・`already_rejected` |
| `restore` | 最後の `rejected` を外し、関係を未確認で戻す | `unknown`・`not_rejected`・`cycle` |
| `assign` | 候補（`none`）・落ちた組・失敗した組に、人が関係を付ける（`by: "user"`・確認済み） | 機械の検査の理由（`mixed`・`role_mismatch`・`cycle` など）・`rejected`・`already_related` |

決めたこと:

- **`confirmed` の中身**: `evidence` は確認した時の根拠の知見の **id の控えだけ**（題は読む口が写しから引く）。
  写しから知見が消えても、確認した事実と根拠の id は台帳に残る。題まで写さないのは、写しを正本にして
  二重に持たないため（写しが無いと確認済みの行は出せないが、それは下の穴）。
- **鍵は 2 種類**: **組の鍵**（2 語の id を文字列順に `|` でつないだもの）は組の件（AI の関係・人が付けた関係・
  取り込み元の行から確認した関係）だけを指す。**取り込み元の行の鍵** `o:<from>|<rel>|<to>`（向きの無い関係は
  id の順・`origin_key`）は、その 3 つ組の行だけを指す（同じ 2 語に別の関係が複数あっても、行ごとに効く）。
  GET の行は全部に `pair`（組の鍵）を持ち、取り込み元の行の `key` が `o:…` になる。
- **取り込み元の行（未確認）の確認**: `o:` の鍵で指す。AI がまだ読んでいない行（`unseen`）を、`by: "origin"`・
  根拠なしの件として組に置いて確認する。`finalize` はこの件を AI の関係と同じ 1 本（`agrees`）として数える。
  組にすでに別の関係（AI・確認済み・人が付けた）があるときは書かず `pair_has_relation`。AI と同じ関係
  （`agrees`）の行は、その組の件を確認する。組に知見が無いのが普通なので、`plan_run` はこの件を `orphan` にしない。
  確認を取り消すと件ごと外れ、取り込み元の行（未確認）に戻る。
- **取り込み元の行の「違う」**: 組の件（無ければ `orphan` ＋ `rejected` だけの件）に、`origin: true` の記録を足す
  （その 3 つ組だけ・2 回送っても同じ）。取り込み元の行から確認した件を組の鍵で「違う」にしたときも、記録に
  `origin: true` を付ける。`origin_check` はこの記録に当たる行を `rejected` と印し、見せない・数えない
  （`shown_relations`・`summarize`）。読み直し（`plan_run`）・外す → 入れ直しでも `unseen`／`disputes` に戻らない。
  AI の関係を「違う」としたときの記録（`origin` の無い記録）は、取り込み元の同じ関係を「まだ読んでいない」のまま
  にする（14d-2a の約束を変えない）。
- **`restore`**: 「違う」で落とした件は関係を未確認で戻す。根拠が無い件（人が付けた・取り込み元から確認した）は
  未確認で残れない（`finalize` が根拠なしを落とす）ので、`reject` が記録に残した `was_confirmed` で確認も戻す。
  関係が台帳に残っていない件（`orphan`・`state` なし）は記録だけ外し、空になれば件ごと消す
  （次の読み直しで聞き直される）。確認を戻すときは「一種」「一部」の輪の検査を通し、輪になるなら戻さず
  `cycle`。`o:` の鍵は、その 3 つ組の `origin: true` の記録だけを外す。
- **`unconfirm` の例外**: 取り込み元から確認した件は台帳から外れ（取り込み元の行に戻る）。人が付けた関係
  （`by: "user"`）は、根拠の有無によらず候補（`none`）に戻る（未確認の人の関係は残さない＝AI の聞き直しとの
  境目を無くす）。`summarize` の `origin` は「違う」とした行を数えない（`origin_check` の合計と合う）。
- **`assign`**: 検査は AI の答えと同じ（`relation_problem`・自分自身・「一種」「一部」の輪）。輪は見せている関係に対して見る。
  `evidence` は組の知見の先頭 3 件。AI の関係が付いている組には付けない（先に「違う」）。
  「違う」とした同じ 3 つ組には付けない（先に戻す）。
- 台帳に `confirmed`・`rejected` がある件は、`plan_run`・`merge_entry`・`finalize`・`strip_unconfirmed`（外す）で
  消えない。「違う」は次の聞き直しでも出ない（`check_answer` の `rejected`）。

口（`knowledge_review.py`）:

| 口 | 中身 |
|---|---|
| `POST /api/knowledge-copies/{source}/relations/review` | `{action: confirm／unconfirm／reject／restore, keys: [1〜50 件（組の鍵か `o:` の鍵）]}` → `{changed, skipped, summary}`。「全部」の指定は無い |
| `POST /api/knowledge-copies/{source}/relations/assign` | `{key, rel, subject: "a"／"b", lang?}` → `{changed, skipped, summary}`。検査に落ちたら 422 `{detail: 文, reason: 記号}`・組が無ければ 404 |
| `GET …/relations` | 行に `confirmed`（`true`・無ければ `null`）・`by`（`ai`／`origin`／`user`）・`rejected`（bool）を足した。`state=all` で全部の状態を 1 回で返す。取り込み元の行の `key` は `o:` の鍵・全部の行に組の鍵 `pair` を付けた |

書く間は `busy_kind` の印 `review` を短く握る（写す・関係を選ぶ・取り込み・外すと排他。走っている間は 409。
review どうしのぶつかりは「別の確認の操作が終わってから」の文で分ける）。
台帳は読む → 書き換える → `finalize` → 保存（既存の保存の関数）。書いたあとの `finalize` は、取り込み元の行の印を
最新にするためで、AI は呼ばない。MCP には出さない。

### 7. 確認済みを正本に置く（PR 14e-1b）

台帳の確認は、書くだけでは MCP・チャットの答えにならない。**台帳の `confirmed` の全件を「あるべき状態」**として、
ストアを合わせる（`asterism.confirmed_store`。AI は呼ばない・決定論）。何度流しても同じ。

| 決め | 内容 |
|---|---|
| 語 | slug は写しの語の id から機械的に（`t-<12 桁>` → `kt_<12 桁>`）。同じ名前（別名も）・同じ種別の用語が既にあれば**乗り**（`themes._match_existing` と同じ判定）、既存の用語は書き換えない。対応は台帳の `stored_terms: {語 id: {slug, minted}}` に固定する。新しく作る語の役割は写しの語のまま（`role_by="machine"`・種類の語だけ） |
| 線 | 述語は `themes.relation_predicate`（`measures` は相手の種別で 2 つに割れる）。来歴は `drafted_by`＝AI の関係を人が確認→`ai`／人が付けた→`human`／取り込み元の行→`machine`・`at`＝確認の時刻（写し直しても変わらない）・`batch`＝`knowledge:<取り込み元>`（100 字を超えたら切り詰め＋ハッシュ）・`reason`＝台帳の AI の理由（200 字以内）か決まった文 |
| 根拠 | `confirmed.evidence` の知見の IRI。置く前に公開中の写しの graph に `kn:Claim` が在るかを 1 回の問い合わせで確かめ、無い物は外して置く（根拠が 0 件でも置く＝人が確認した事実を優先）。引く道は `evidence.resolve_evidence` が知見（題＝`rdfs:label`・`kn:sourceUrl`・`dataset_id` は `null`）も引くよう広げた。**取り下げ済みの写しからも引く**（データは残る）・削除済みは引かない |
| 置けなかった件 | 台帳の確認は消さない。件に `store: {ok, reason?, at, of, line?}`。理由の記号は `role_mismatch`・`kind_mismatch`・`cycle`・`self`・`error`。`error` 以外は、確認が変わる（`of` が変わる）まで置き直さない。`error` は試した回数 `tries` を控え、3 回落ちたら確認が変わるまで試さない |
| 外す | 取り消し・「違う」・取り込み元の行を外す（未確認を消す）のあと、**`knowledge:` の線のうち、どの台帳も確認していない線**を外す。話・人が置いた線・ほかの取り込み元が確認している線は外さない。**この段の語**は slug の形（`kt_` ＋ 12 桁）で決める（どの取り込み元が作ったか・台帳の控えには依らない。名前一致で `kt_` の語に乗った場合も同じ）。外す条件は「ストアで線が 1 本も触れていない・どの台帳の『確認済みで置けた件』も使っていない・話が使っていない」（線が触れていれば `remove_term` が `TermHasLines` で断る）。台帳の `stored_terms` は確認済みの件が使う語の分だけ残す。取り込み元を外したとき（取り下げ）は何も外さない（裁定④）。線を置く・外した回は最後に `recompute_wired`（話の確定・取り消しと同じ） |
| いつ流すか | review・assign の口が台帳を保存した直後、同じ握り（`busy_kind` の `review`）と話の確定と同じ排他（`themes_lock`）の中で。回す順は その操作で指した件 → まだ試していない件（14e-1 で先に付けた確認）→ 確認が変わった件 → 前に `error` だった件、1 回 50 件まで。取り込みジョブの最後にも、試す件が無くなるまで追い付かせる（最大 40 回） |
| 失敗 | 置く段が落ちても review・取り込みは失敗にしない（返りの `store.error`）。線を置いたあと台帳の保存が落ちても、次の回は「ストアに線が在る」件として拾うので壊れない（収束する作り・巻き戻しは持たない）。「ほかの台帳を読む → 置く・外す → 自分の台帳を保存 → `knowledge_sources.json` を保存」は**1 つの排他（`themes_lock`）の中**でやる（保存の前に別の取り込み元が同期すると、保存前の台帳を読んで置いたばかりの線を外すため） |

口の返り（足すだけ）: review・assign の `store: {placed, removed, failed: [{key, reason}], backlog_failed, remaining, attempted}`（`failed` は**その操作で指した件**のうち置けなかった件だけ。追い付きで落ちた無関係な件は数 `backlog_failed` だけ）。`GET …/relations` の
行の `from`／`to` に `term_iri`（置いた語だけ）・行に `store: {ok, reason?}`（確認済みで置いた結果がある件だけ）。
`/api/sky` に用語の役割は**まだ足していない**（`terms[]` も最上位も欄の集合を完全一致で固定する既存テストがあるため。別の口を決める）。

**知識の問い（MCP・星図から引く）**: 確認済みで**ストアに置けた**関係だけに、`pair_relations.questions` と同じ数え方
を当てた問いを、取り込み元ごとに `<registry>/vocab-shared/knowledge_sources.json` に置く
（`asterism.knowledge_sources`）。形は `{version: 1, sources: {<取り込み元>: {title, updated_at, minted, uses, relations,
selections: {<kq_ の名前>: {mode: "knowledge", op, target_slug, target, title, direction?}}}}}`（選び方は話の
`selections` と同じ形）。名前は `themes.knowledge_tool_name`。確認・取り消し・「違う」・追い付きのたびに、その取り込み元
の分を作り直す（消えた問いは消す・変わらなければ書かない）。話に同じ名前の問いが在れば話を正とし、ここには作らない。
取り込み元を外しても残す（確認済みは残るため）。読む所は 2 つだけ足した: MCP `answer_knowledge_question`
（`themes.json` に無い名前をここから引く・返りの形は不変）と `sky_view._knowledge_question_selections`（用語の点の
「問い」）。チャットは台帳の走者で答えるので、ここは読まない。

**`themes.json` に入れなかった理由**: 話として画面に出る・利用者が消せる・上限（概念 120 など）に当たる。読む所が
30 か所を超える（`chat_turns` 8・`themes_routes` 11・`chat_seed`・`chat_point`・`consult_graph_routes`・`chat_routes`・
`sky_view`・demo-agent・MCP ほか）。別のキーを足す案は `load_themes_file`／`ensure_migrated` が `themes` 以外を落とすので不可。
**話の後始末**（`remove_theme_cascade`）はこのファイルを見ない（話と取り込み元は別の持ち主）。取り込み元の語に線が
触れていれば `remove_term` が `TermHasLines` で断るので、話を消しても取り込み元の用語は外れない。話の確定が置いた線と
同じ線を、取り込み元が「既にある」として置き直さなかった場合に、話を消すと線が消えるが、次の同期が「ストアに無い件」として
置き直す。

**§7 で直さなかった点（残した穴）**:

- チャットの AI は、取り込み元の問い（`kq_…`）を道具として持たない（チャットは台帳の走者で答える。別の PR）。
- 話を消すと、話が置いた同じ線は消える（取り込み元は「既にある」として置き直さなかった場合）。次の同期で置き直す。
- 行の `term_iri` は、用語が手で消された後も古い値を返しうる（画面は図に無ければ台帳の点で描く）。
- 根拠の論文の本数の数え方で、知見の束は題 1 つを 1 本と数える。

## 退けた案

| 案 | 理由 |
|---|---|
| 全部の組を 1 回で読ませる | 入力が長く、弱いモデルで形が崩れる。途中で止めたときに何も残らない |
| AI に語を作らせる・関係の名前を付けさせる | 同じ意味の別名が増え、問いで引けない。語は取り込み元のトピックから機械で作る（14b） |
| 意味を言えない組に「関連する」を付ける | 問いで役に立たない線が大半になる |
| 確からしさを AI に言わせる | 取り込み元が知見ごとに既に持っている。AI の仕事を増やさない |
| 話の下書きに置く | §3 |
| 取り込み元が知っている関係をそのまま信じる | §4 |

## 残した穴

- 台帳を地図と「関係」のタブに出す・候補の切り替え・チャットの入口と返事・未確認の関係を答えに使う・
  確認と「違う」・確定（知見の IRI を根拠にする）は 14d・14e。それまで、台帳は api の読む口からしか見えない。
- 知見（`kn:Claim`）を根拠として確定するには、`themes._require_live_evidence`・
  `crosswalk_runtime.drop_evidence_in_graphs` に、論文の文（`doco:Sentence`）以外の分岐が要る（話の確定の道。
  確認済みを置く道は 14e-1b で `evidence.resolve_evidence` を広げて引ける）。
- 写しを外したときの台帳の後始末（14d）。
- ジョブは台帳を読んでから保存するまで数分かかる。そのあいだに、ほかの口が台帳に書いたものは消える。
  確認と「違う」の口（14e）は、同じ取り込み元のジョブと排他にする。
- 「一種」と「同じもの」をまたぐ輪（x は y の一種・y と z は同じ・z は x の一種）は、台帳では通る。
  止めるのは確定のとき（`assert_alignment`）。
- 普段使いの弱いモデル（OpenAI 互換の公開モデル）での実測はしていない。上の「弱いモデル」は代役で、API 越しの形の崩れ
  （JSON でない返事・聞き直し）は測れていない。聞き直しと失敗の扱いはスタブで検査している。
- 集合に無くて付けられない関係が、「言えない」の 3 分の 1 ほどを占める（条件や手段になる・合成を促す／妨げる・併用・比較）。
  足すかどうかは、この数を見て別に決める。
- 予定・計画の文（「〜を測定する予定」）が根拠でも、確からしさの印は付かない（取り込み元の `epistemic_status` が
  `interpretation` などになっているため）。

- 確認した関係を **写しが取り下げ済みの取り込み元** では一覧に出せない（読む口が写しの名前・知見の題を引くため）。
  台帳には残るので、入れ直せば出る（14e-1）。
- 取り込み元の行から確認した件の語が写しから消えたとき、`summary` には数えられるが一覧（読む口）には出ない（14e-1）。
- 取り込み元の行から確認した件は、取り込み元がその関係を消しても台帳に残る（14e-1）。
