# 全体グラフ（値でつなぐ網）

状態: 下書き（担当が書いた。結合時に本体が整える）。契約メモ: `contract_network_view.md`。

## 0. 経緯

- 利用者は「TBox／ABox を Graphium のような全体グラフで見たい」と言い、v0.51.0 の全体図（種類だけの設計図）を見て
  「DBpedia のような複雑なグラフを想像していた」と言った。
- 手元の実データ（約 3,800 件・件どうしの線 約 4,500 本）で、全部の件を点にすると星形の円が 3 つになるだけで
  読めない（XRD の 3,001 点がカード 1 枚、年ごとの記録 682 件が取り込みの記録 1 件につながる）。
- 分類のような値（地域・年）を点にし、来歴の線を外し、同じ相手にしかつながらない件の群れを束にすると、
  776 点の網になり、国が地域ごとに寄り、年が輪になる。利用者の判断で「中間 B」を試しに作る。

## 1. 点にする規則（決定論・`asterism.network_view.network_view`、`GET /api/network`）

| 点 | 規則 |
|---|---|
| 件 | IRI の主語・IRI の目的語。`xw:CrosswalkLink` は点にしない。種類は `subject_tools._representative_kind` |
| ハブ | ハブ graph で、PROV でも `xw:CrosswalkLink` でもない型を持つ件（`_hub_entity_type_filter` と同じ判定） |
| 値 | graph ごと・述語ごとに文字の値を数え、値の種類 ≤ 50 かつ 使われた数 ÷ 値の種類 ≥ 3 の述語の値。名前・説明の述語（rdfs:label ほか 8 つ）は除く。id は「述語 IRI＋値の文字列」＝同じ述語を使う別のデータセットの同じ値は同じ点、別の述語の同じ文字列は別の点 |
| 束 | 同じ種類で、つながる相手（件・値の点・述語・向き）がまったく同じ件が 20 件以上 |

- 線は rdf:type 以外の IRI→IRI と、件→値。**PROV の述語は既定で外す**。PROV の型だけを持つ件は、線を外すと
  孤立するので既定では点にしない（`include_prov=true` で線も点も入る）。
- 線の数 0 の点は出さない。読む範囲は `canonical_graphs` だけ（draft は読まない・公開 0 件なら SPARQL を投げない）。
- `set_spec`（一覧で開く）はサーバが完成形で返す（O59）。値＝いちばん件数の多い種類＋`eq`、束＝相手の件が 1 つに決まるときだけ。

## 2. 色と大きさ（画面）

- **色は 8 種類まで**。人の目が確実に見分けられる分類の色は 8 色前後で、全種類に別の色を配ると破綻する。
- **色は種類の IRI のハッシュの席で決める**（順位で配らない）。好みの席 = `h % 8`（`h` = `fnv1a(IRI, salt)` の上位 16 bit を下位へ混ぜた値 `h ^ (h >>> 16)`。混ぜないと番号違い・大文字小文字違いの IRI が必ず同じ席にぶつかる）、埋まっていれば
  次の空き席。順位で配ると、データが増えたときに同じ種類の色が変わる（実例: 「国」が手元のデータでは桃、
  同梱の見本では橙だった。`kinds` の順位が 3 位と 2 位で違ったため）。ハッシュなら下位に種類が増えても
  上位の色は変わらず、ぶつからない限り同じ種類はどのデータでも同じ色になる。
- **凡例の種類を押すと、その種類だけに色が付く**（案 B・8 種類まで）。凡例は全種類の一覧（件数つき）で、
  押していない種類は灰、絞り込み中は外の件・束と、それだけにつながる線を薄くする（値・ハブは網の骨組みなので薄くしない）。
  載せた／選んだ点の強調は絞り込みより優先。見え方は純関数（`nodeAppearance`・`edgeAppearance`）。
- 値・束・ハブは色でなく形と大きさで区別する（値＝濃い灰・ハブ＝青・束＝大きな丸で中立の色）。
- データセットごとには塗らない。大きさは次数（束は中の件数）の表示中の最小〜最大の対数・面積比例
  （全体図の `sizeScale` と同じ考え方）。
- 案 A（上位構造の分類で塗る）は §5。

## 3. 配置は決定論

「力学配置を採らない」は全体図（種類の設計図）の決定。こちらは中身の網で、初期位置を点の id のハッシュで固定し、
ForceAtlas2 を固定回数だけ同期で回して止める。乱数・時刻を使わないので同じデータは同じ絵になる。

- **連結成分ごとに FA2 を回し、大きい順に行へ並べる**。1 つで回すと、小さなまとまり（XRD のカードなど）が
  網の縁に押しつけられ、名前が重なった。
- **線形の FA2（重力 0.1・scalingRatio 2）**を採る。実データで「同じ地域の国どうしの距離 ÷ 違う地域の国どうしの距離」を
  比べて選んだ（LinLog 1.0・重力 1 で 0.81、採用した設定で 0.23）。
- 繰り返し回数は点の数で 120〜500。探した点に寄るときは、相手まで入る広さにする。

## 4. 規模と上限

点が `max_nodes`（既定 5,000）を超えたら、ハブ・値・束を残し、件は次数の多い順→IRI 順で残して `truncated: true`。
SPARQL の行が `max_rows`（既定 200,000）を超えても `truncated: true`。

## 5. 上位構造との接続

`asterism.shared_vocab.upper_map(client)`（別の作業で設計中・まだ main に無い）があれば、値の点は上位の項目で
まとめ、色は上位の分類（`group_iri`）で塗る（案 A）。無ければ今の振る舞い（`class_iri` で塗る）。
この差し替え口は f06fe018 で入った（`kindKey = group_iri ?? class_iri`）。
