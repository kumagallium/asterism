# ADR: Ask をチャットにする — スレッド（履歴）は手元、エージェントは無状態

- **状態**: 実装済（branch `feat/ask-chat`・2026-08-17）
- **決定者**: kumagallium + Claude Code
- **起点**: ユーザー要望「現在の Ask は単体の質問だが、AI チャットにできないか。
  チャット履歴一覧とチャット欄があるよくあるデザインをベースに直してほしい」。

## 問題

Ask（`#/ask`）は **1 問 1 答**だった。質問→回答カード（引用・品質メモ・
使用 SPARQL）→来歴パネル、で完結し、次の質問を打つと前の回答は消える
（タブ往復用にモジュール変数で直近 1 件だけ保持）。研究者の実際の問い方は
「ZT が最も高いのは？」→「その試料の組成は？」→「同じ論文の他の測定は？」と
**前の答えを踏まえて掘る**もので、毎回すべてを言い直させるのは道具として弱い。
また過去に何を聞いて何が返ったかが残らないため、引用できる事実に辿り着いた
経路を後から再訪できなかった。

## 決定

### D1. 会話の単位＝スレッド。UI は「履歴一覧＋会話＋入力欄」の 3 ペイン

- 左＝スレッド一覧（今日 / 昨日 / 過去 7 日 / それ以前でグループ、
  「＋ 新しいチャット」、行の削除は inline 2 段確認）。
- 中＝会話（質問は右寄せの吹き出し、回答は従来の**回答カードそのまま**＝
  検証済/未検証バッジ・Markdown 回答・引用カード・データ品質メモ・使用 SPARQL 開示）
  ＋下端に固定の入力欄（Enter 送信・Shift+Enter 改行・IME 確定 Enter は送らない・
  自動伸長・1 スレッド 1 問ずつ）。
- 右＝来歴パネルは**引用をクリックしたときだけ**開く第 3 列（× で閉じる・Esc）。
  常設だった空パネルは廃止（会話の幅を優先）。狭幅では来歴はオーバーレイ、
  一覧はトグルで出るスライド式に落ちる。
- ルート: `#/ask` = 新しいチャット（**最初の送信までスレッドを作らない**＝空
  スレッドが溜まらない）、`#/ask/<threadId>` = 既存スレッド（リロード・戻る/進む
  で維持。最初の送信時は `replace` で URL を差し替え、戻るは Ask に来る前へ）。
- 「引用できる事実」の主役は変えない: 回答の生成経路（型付き優先＋escape）・
  バッジ・引用・SPARQL 開示は 1 ターン＝1 回答カードとして**そのまま**残る。
  チャット化は「聞き方」を変えるだけで、「答えの根拠の見せ方」は変えない。

### D2. 履歴の置き場＝ブラウザ（localStorage）。エージェントは無状態のまま

- スレッドは `ui/src/askThreads.ts` が `localStorage`
  （`asterism.ask.threads.v1`）に保持する。上限 60 スレッド（古い順に落ちる）、
  容量超過時は古い半分を捨てて再試行、別タブの更新は `storage` イベントで追随。
- **サーバ側に会話を持たない理由**:
  1. 本番は**一つの合言葉を全員で共有する**ログイン形態（ADR
     production-deployment）で、ユーザー識別が無い。サーバ保存＝全員の質問が
     全員に見える。手元保存は**その人の質問はその人のブラウザにだけ**残る、
     プライバシー既定として正しい方。
  2. デスクトップ（ローカルファースト）配布はそもそも手元完結。同じコードで
     そのまま成立する。
  3. demo-agent は registry を**読み取り専用**でマウントする消費層で
     （`compose.prod.yaml`）、書く場所を持たない。持たせない方が層の責務が
     はっきりする。
- 送信時、UI はそのスレッドの**完了した過去ターン**（質問＝回答テキスト＋引用
  IRI の一覧）を `history` として `POST /demo/ask` に同送する。エージェントは
  それを LLM の messages 先頭に**再生**するだけで、状態を持たない
  （リクエスト完結）。実装: `demo-agent/app.py` の `AskRequest.history` と
  `_prior_messages`。

### D3. 履歴の扱い＝サニタイズと窓、事実は毎ターン道具で取り直す

- `_prior_messages` は手元由来の履歴を信用しない: 不明 role / 空ターンを落とし、
  同 role 連続を結合（失敗した回答は質問だけが残るため）、**直近 12 ターン**
  （6 往復）だけ、1 ターン **4,000 文字**で切り詰め、user 始まり・assistant
  終わりに正規化（未回答の末尾質問は落とす＝新しい質問に混ぜない）。
- 過去ターンの**ツール呼び出し/結果は再生しない**（ユーザーが見た回答テキスト
  だけ）。system prompt に「前のターンは参照解決に使ってよいが、数値・IRI は
  **このターンで道具を呼んで取り直す**。記憶から再引用しない」を明記。
  引用の再現性（引用 IRI はそのターンの結果に実在する）を会話でも保つため。
- 履歴が使われるのは LLM ルーティング経路のみ。キー無しの型付き showcase は
  設計上 1-shot（キーワード → 宣言ツール）で、履歴は無視する。
- 契約は後方互換: `history` 省略＝従来どおりの単発質問（`{question}` のみ）。

### D4. 決定論の維持

- スレッド題名＝最初の質問の先頭 48 文字（LLM でタイトル生成しない＝課金ゼロ・
  決定論）。
- 会話履歴による**追加のトークン消費**は system prompt（スキーマ）に比べれば
  小さいが、上の窓で上限を持つ。使用量台帳（`/api/usage`）には従来どおり
  1 質問 1 行で記録される。

## 却下した案

- **サーバ側スレッド保存（api の `/api/ask/threads`）**: 上記 D2 の理由（共有
  ログイン＝全員に見える・demo-agent は読み取り専用・層の責務）。ユーザー識別が
  入る日が来たら、`askThreads.ts` の store 境界（load/save）を差し替える設計に
  してある。
- **エージェント側でセッション ID を持つ**: 再起動で消える・複数レプリカで
  破綻・手元と二重管理になる。無状態＋履歴同送の方が単純で壊れにくい。
- **過去ターンのツール結果まで再生**: 文脈は濃くなるがトークンが跳ね、
  「古い結果を新しい答えとして再引用」を誘発する。上の「毎ターン取り直す」で
  代替。

## 残タスク

- スレッドの名前変更（現状は最初の質問固定・削除のみ）。
- 実 LLM での多ターン dogfood（本 PR の検証はモックとユニット＝messages 前置の
  形まで。実キー環境で「その試料の…」の後追いが引用付きで返ることを確認する）。
- 送信中の「停止」（fetch 中断・サーバ側は止まらないため UI 解放のみ）。
- 実運用で 60 スレッド上限 / 4,000 文字窓が窮屈なら数値を見直す。
