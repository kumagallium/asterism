## 1. きっかけ — 「ことば／線」は構造の名前を人に見せていた

v0.53.0 の「ことば」画面（問いから始める・地図・一覧と鋳造フォーム・線）を見た利用者の評価（2026-10-19）:
「ことばも線も登録の UI がとても分かりづらい。『線』という言葉も分かりづらい。線の UI は人に見せられるデザインではない」。
あわせて、製品の形として「データセット経由のボトムアップと、コンピテンシー質問経由のトップダウンの 2 入口が
どの画面からでも前面にあり、トップページが知識グラフの可視化で、2 つの入口から育つ体験」を求めた。

| # | 原因 | 根拠 |
|---|---|---|
| 1 | 画面がデータ構造の順（問い・地図・語・線）で並び、「そこで人がすること」（K34）になっていない | `SharedVocabView.tsx` の 4 節 |
| 2 | 操作の前に 3 種の端点（種類／共有のことば／標準の語）と 3 種の関係（≡・⊂・→量）を知らないと何もできない。ID（slug）は開発者の概念 | `VocabTermForm.tsx` |
| 3 | 「線」は実装（alignment triple）の名前。人の意図は「これはあれの一種」という判断で、かんたん③と同じ型なのに別の作法（丸を 2 つ選ぶ）になっていた | 地図の pick モード |
| 4 | 問いは必須なのにフォームの最後に来る。利用者の頭は「問い → 要る語」 | 鋳造フォーム |
| 5 | 問いのリストが一級の対象でなく、「リストごとに上位が育つ」が無い | §2.3 `for_terms` |
| 6 | 外部 UX レビュー（2026-10-01）: 科学者の目的「試料を選ぶ → 測定結果を見る」への導線が構造の話に埋もれる | — |

設計は 3 角度の案（星図ホーム・ふたつの入口・問いの帳）を 3 レンズ（実験化学者・製品原則・規模）で採点して統合した。
採った部品と退けた部品は §4。

## 2. 決定

### 2.1 名詞は 4 つ。関係は名詞にしない

| 画面の名詞 | 英 | 旧 | 何か |
|---|---|---|---|
| データセット | Dataset | — | 置いたファイルから作った 1 つ分の事実 |
| テーマ | Theme | 問いのリスト | 知りたいことの問いのリスト。上位構造が育つ単位（段階 4） |
| 問い | Question | 観点・CQ | 答えてほしい 1 文。閉じた選択から機械が実行文と SPARQL を組む |
| 用語 | Term | 共有のことば・共通の言葉・ことば | 複数のデータセットの種類・項目をひとつの名前でまとめる語（`sv:`） |
| 標準用語 | Standard term | 標準の語・標準のことば・接地 | QUDT・schema.org など世界共通の語 |
| 決めたこと | Decisions | 線・線の一覧 | 人が文で決めた関係の記録（日付つき・取り消せる） |
| つながり | Connection | — | 値の一致で件どうしを結ぶ仕組み（変えない） |

関係は常に文で言い、文で見せる: 「A は B の**一種**」「A と B は**同じもの**」「この項目の量は **○○**」「標準用語 ○○ と同じもの」。
「星」「星座」「線」は画面の文字に使わない（比喩は図の見た目だけ・O54）。

### 2.2 ナビは 5 つ＋設定。入口は 2 つをホームに常設（2026-10-20 改訂）

| ナビ | すること | 吸収する画面 |
|---|---|---|
| ホーム | 星図を見る。両方の入口。最近の育ち | ホーム・用語の地図・全体グラフ（「中身まで見る」） |
| 知りたいこと | テーマを作る・育てる。出会いの表 | ことば・⑥の「自分の問い」の写し先 |
| データ | ファイルを置く → かんたん 7 段 → 公開。追記・差し替え。つながり | データセット・つながり |
| 見る | 1 件・一覧・カード（試料を選ぶ → 測定結果を見る） | ワークスペース |
| 質問する | 公開済みに自然文で聞く。答えられなければ「テーマに入れて育てる」 | 質問する |
| （下段）設定 | 設定。「開発者向け: SPARQL を直接書く →」は設定の「このサーバ」の末尾 | 「決めたこと」はナビに出さず、用語のページと星の横（`#/decisions?about=<IRI>`）から辿る。アクティビティは「データ › 記録」（`#/data?tab=activity`・旧 `#/jobs` はここへ） |

入口 2 つ「＋ データを置く」「？ 知りたいことを書く」は**ホームの「答えられる問い N / M」の行の右**に置く（`ui-guidelines.md` §2 の
「グローバル作成ボタン無し」の唯一の例外。上部バーは題と言語切替だけ — 2026-10-20 改訂。当初はどの画面でも上部バー右に置いたが、左ナビと重なるという利用者の指摘で 1 か所にした）。「質問する」と「知りたいこと」は別の画面にし、橋を 2 本架ける
（答えられない → テーマに入れて育てる／答えられるようになった問い → 質問するの道具）。
データから作る 7 段（①入れる → ⑦公開する）は**骨格そのまま**。③⑤の提案文と出入口だけ変える（§2.5）。

### 2.3 ホーム＝星図（紙の星図・決定論・育つ）

| 要素 | 描き方 | データ源 |
|---|---|---|
| 種類 | 星（`--entity`）。大きさ＝件数（表示中の最小〜最大で対数・面積比例） | `kind_counts` |
| データセット | 星座（中の種類を細い線で結ぶ＋名前。枠線は引かない） | 取り込みルール |
| 用語 | 上の帯（`--activity`）の札。種類から用語へ線＋矢じり（一種）。星が無い用語は薄い塗り＋「まだ星がない」（点線は使わない） | `vocab/shared`・alignment graph |
| 標準用語 | 地平線（`--accent`）の帯。画面に固定。用語の札の下に「≡ cmso:Material」 | `known_vocabs` |
| つながり | 星座のあいだの橋の段に青い星 | crosswalk hub |
| 問い | 図の点にしない。右の「知りたいこと」に輪（答えるデータセット／公開データセットの全数） | `wired.json` |

- forest の明るい地に役割の色を薄く塗る。**夜空（暗い地）は採らない**。配置は決定論で、追加では既存の星座を動かさない（増分配置）。
- 種類 ≤ 60 かつ データセット ≤ 8 は星。超えたらデータセットを 1 つの丸に畳む（俯瞰の 2 段規則）。規模試験（S／M／L／XL）を最初の PR に含める。
- 星を押す → 右に「◯◯ を見る」（主ボタン）と「ひとこと決める」（§2.5）。公開直後・テーマを置いた直後に新しい星／札が 1 度だけ灯り、「答えられる問い 5/7 → 6/7」が数え上がる。「静かな表示」と図と同じ内容の表を常設。図の元データは 1 つの JSON（`GET /api/sky`）で、サーバ無しでも描ける。
- 土台は canvas 2D（参考実装 `../design/sky-chart-mock/skychart.js` の移植・依存なし）。点は 200 未満で足り、headless の撮影で WebGL の細工が要らない。点が数百を超える規模になったら sigma（全体グラフ）に替える。React Flow の地図は「データセットの詳細 › 設計の中身」に残す。

### 2.4 「知りたいことから作る」（v2・3 段・知識の図・2026-10-20 改訂）

6 段（v1・2026-10-19）は、AI を「問いの名詞抜き」にしか使わず、確認を構造の表でさせていたため「目が滑る」「知見（散乱要因）が出ない」と評価された。v2 は 3 段にし、AI に**知識の図**を下書きさせる。設計の記録は `ui-redesign-2026-10-19/design.md` §15。

| 段 | 人 | AI（下書き） | 機械（決定論） |
|---|---|---|---|
| ① 書く | 問いを 1 行でも（テーマ名は任意） | — | 下書きを保存 |
| ② 下書きをたしかめる | 図と文を見て ✕ で外し「N 件をまとめて確定」。点を選んで「ここを広げる」。手で足す。問いごとの答え方を選び直せる | 概念（種類・項目）・関係（一種／同じ／量は／一部／下げる・上げる・変える）・理由 1 行・問いごとの答え方・「欲しいデータ」1 行 | 完全一致の照合（2 文字以下の別名は使わない）・述語ごとの種別表・循環（一種・一部は拒む、下げる系は許す）・ID の導出・「知識 N・データ N」 |
| ③ 置く | 一覧（概念・ID・関係・問い）を見て「置く」 | — | 1 操作で保存（失敗は全部戻す）・来歴（draftedBy／batch／reason）・`wired.json`／`knowledge.json` |

- **関係は 9 述語**（既存 5 ＋ BFO `part of`・RO `negatively/positively regulates`・`regulates`）。自前の `sv:` の述語は作らない（`sv:` は slug の名前空間）。種別は述語ごとの表（`crosswalk_runtime.RELATION_SHAPES`）で検査する。
- **答え方は 2 系統**: データで答える（件数・範囲・上位）と知識で答える（`factors`／`parts`／`kinds`・alignment graph への閉じたテンプレート・閉包は 1 段・`asterism.knowledge`）。指標は「知識 N・データ N」の 2 つ。MCP には `answer_knowledge_question` で出す。
- **公開範囲（利用者裁定 2026-10-20）**: 人が確定した知識の関係が 1 本以上ある語は「孤立」と見なさない（`wired ≥ 1 または knowledge ≥ 1`）。
- **概念ごとの既定の問いは作らない**。門は「テーマの問いに関係でつながらない用語は作らない」。テーマを外すと、他で使っていない概念と関係も消える（テーマ単位の取り消し）。累積はテーマあたり概念 120 まで。
- **下書きの札**: ③で置くまで、星図の上の帯に枠だけの札＋「下書き」の印。認証つきの別口 `GET /api/themes/drafts/sky` で返し UI が合成する（`GET /api/sky` は公開済みだけ）。データ 0 件でも出る。確かめていないものは Ask／MCP に出さない。
- **育てる**（6c）: 問いを足す → その分だけ AI が広げる。データを公開 → 名前の完全一致だけ機械が下書きの線にする。AI の候補は、ホームで人が「AI に結ばせる」を押したときだけ（冪等・却下は保存）。公開の処理に AI は足さない。
- **「欲しいデータ」**は問いごとに 1 行（型紙の言い換え）。論文の推薦は出さない。
- AI に渡すのは問いの文・既存の用語と標準用語の名前・（広げるとき）いまの概念の名前だけ。**AI は SPARQL・コード・IRI を書かない**。AI が未設定でも手入力で同じ画面が動く。
- 方法論との関係: Grüninger & Fox（1995）のコンピテンシー質問法に沿う（非形式の CQ → 用語 → 形式の CQ（閉じたテンプレート）→ 公理（9 関係）→ 評価）。完全性の証明は「データと知識で実際に答えられるか」の実行に置き換えている。ボトムアップ（データから作る）は同法の外で、混合法として組み合わせる。

### 2.5 「ひとこと決める」と「決めたこと」

どの入口（星図・かんたん③⑤・テーマ④⑤・出会いの表）でも同じ 1 つの部品:
文が 3 つ「◯◯ は [用語] の一種です」「◯◯ と [用語] は同じものです」「当てはまるものは無い（提案を外す）」＋「あとで決める」（K29）。**初期選択なし**。
選ぶと帰結（「問い『…』に答えるデータセット 0 → 1」）を読み取り専用の試算で見せ、「そう決める」で保存（alignment graph・述語は閉じた 5 つ・循環は拒む）。
「決めたこと」は 1 行 1 文の台帳（日付・根拠の問い・取り消す）。切れている関係は消さず取り消しだけ許す。「線を引く」モード（丸を 2 つ選ぶ）と線の 5 タブは廃止。

### 2.6 出会う場所と指標

出会う場所は 4 つ（星図・かんたん③⑤・テーマ⑤・出会いの表＝問い × データセット）。指標は 1 つ「**N データセットが答える**」。

## 4. 退けた案

| 案 | なぜ退けたか |
|---|---|
| 夜空（暗い地）の星図 | forest 単一テーマと「薄く塗る・点線は嫌い」に反する。紙の星図で同じ構図を保てる |
| 関係を入れ子の輪（包含）で描く | 1 つの種類が複数の用語に属する多対多が描けない。線＋矢じりの 1 段で描く |
| トップダウンを 7 段にする | かんたんより軽くならない。ID の段を外し、⑥で一覧して確かめる |
| ID を「詳しく」の奥に隠す | IRI を形作る値を人が確認しないまま保存される。⑥で見せる |
| 「質問する」と「知りたいこと」を 1 画面に統合 | 「いま聞く」と「育てる」の判断を毎回させる。橋 2 本で結び、統合は将来案 |
| 問いを図の点にする | 点が増えて読めない。右の輪（答える／全数）にする |
| LLM に SPARQL を書かせる | 引用できる事実の主軸に反する（従来どおり） |
