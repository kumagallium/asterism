## 1. きっかけ — ④「ID のつけかた」だけ異様に難しい（利用者評価 2026-08-31）

> 上から下までの流れを迷いなく、ユーザーができる気がしない。客観的に難しくないですか？

実測が裏付ける。kind-splitting の実装当日（2026-08-31）、この画面には利用者の実使用から
**6 件以上の UX 欠陥**が連続で見つかり、すべて「エディタに注意書きとボタンを足す」対症で
直した。足すほど流れが壊れた。マニュアルの説明もこの段が全ステップ中いちばん長い。

難しさの正体は 3 つ:

1. **1 画面に 3 つの抽象概念**（種類・ID・帰属）— 22 行 × 2 コントロールの正規化エディタに
   なっており、解決策の語彙で人に問うている
2. **偽のジレンマ** —「載せたい ∧ 外部キーにもしたい」は既に両立している（☑ で項目は
   参照に変わるだけで外れない）のに、チェックとドロップダウンが排他に見える
3. **逃げ道の増殖** — D2/D4/カード修理/相談を足すたびにボタンが増え、既定の読み順が消えた

利用者の対案が本 ADR の骨子:「**ユーザーにとって簡単なところから入れていくフローにする。
そうすることで確率論から決定論的になり、AI も楽に設計の精度を上げられる**」。
使い捨てモック（実データ = XRD 参考カード・実 ShapeGraph）で 3 巡の評価を経て確定した。

## 2. 決定

### D1 判断の 3 分法 — 測る・聞く・導く

骨格に必要な事実を全部並べ、出どころを 1 つに決める。**機械の推測が黙って残る場所を
ゼロにする**のが目標。

| 決まるべきこと | 決め方 | どこで |
|---|---|---|
| カードと行の分割 | **測る**（全行同値の放送列 = カードの項目） | — |
| 行の種類の ID | **測る**（一意性の実測 + スコープ規則。測定値キーは既存 K7 ⚠） | — |
| 各列の意味・単位・取り込む | **聞く**（現行のまま・変更なし） | ③ |
| 他のデータにも出てくる値 | **聞く**（列ごとに ☑ 1 個） | ④（新設） |
| カードの ID | **導く**（④の ☑ から。曖昧なときだけ④末尾で 1 問） | ④ |
| つながる受け口の箱 | **導く**（☑ = 箱。ID になった値は箱を作らない） | ⑤ |
| 種類の名前 | AI の下書き + ⑤で変更 | ⑤ |
| 任意の分割（1 行に 2 つのもの） | ⑤の「直す」 | ⑤ |

### D2 ④「外とのつながり」を新設する（1 画面 1 判断）

③に 4 つ目の判断を足すのではなく、**独立した段**にする（利用者裁定）。聞き方は
「外の世界の公式な名前か」ではなく「**他のファイルや他の人のデータにも、同じ表記で
出てくる値はどれか**」— この言い換えで、カタログ番号だけでなく化学式のような
「決まった書き方」も選択肢に入る（実測: 旧文言では人も AI も組成を選ばなかった）。

- 冒頭に**身近な連結例**を常時表示: レシピの表とスーパーの価格表が食材名「にんじん」で
  つながり、「にんじんを使うレシピと、いまの値段」を一度に引ける
- 基準は畳まない: 付けるもの（他でも同じ表記で出てくる言葉・番号。名前、化学式のような
  決まった書き方、DOI・カタログ番号）／付けないもの（ファイル内だけの通し番号・自由記述。
  測定値は選択不可）／**付けても項目は外れない**（参照に変わるだけ）
- **AI の事前チェックは置かない**（利用者裁定: 精度が悪いと惑わすだけ）。「迷ったら AI に
  相談」は任意の入口として残す
- S2 の q2「この番号は他のファイルにも出てきますか？」は④に吸収して廃止（1 問減る）

### D3 カードの ID は④の答えから導く（機械の特別扱いをやめる）

これまでカードのキーは機械のヒューリスティック（先頭の放送識別子列）で、**選んでいない
No が設計に現れる**違和感の source だった（利用者指摘）。導出規則:

```
④で ☑ したファイル単位の値が
  ├ 1 つ   → それがカードの ID（人が選んだことになる）
  ├ 複数   → ④末尾で 1 問「この表 1 枚を名指すのはどれ？」（＋わからない=機械に任せる）
  └ 0     → 機械が仮置きし、⑤で「⚠ ID は仮です」と明示して選び直しへ誘導
```

ゼロ ☑ 時の扱いは**仮置き + 明示**とする（利用者裁定 2026-08-31。合成のファイル由来 ID は
IRI の引用性を落とすため将来オプション）。2 ファイル目からは既存の scope 検査が実測で
衝突を検出する。**☑ した値がその種類の ID になったときは受け口の箱を作らない** —
種類自身が受け口（カードは No で外から名指しできる）。

### D4 ⑤「できた形をたしかめる」— グラフ主役の確認画面

④までの答えと検査の事実から**決定論で組み立てた形**を見せ、「合っていれば 1 押し」を
既定路にする。22 行の表・載せる種類のドロップダウンは既定で出さない。

- 箱のラベルに件数を入れる（`カード · 1 件` `ピーク · 47 件`）。**色分けは 1 つだけ**:
  琥珀 = ④で ☑ した受け口（緑の「ファイル全体」特別扱いは廃止 — 件数で伝わる情報を
  色で重複させない・利用者指摘）
- **項目は既定で表示する**（利用者裁定 2026-08-31: 属性のつき方への違和感が「分ける」の
  入口になる）。全部並べると図が潰れるので、先頭 n 件 + 「ほか n 項目」で打ち切る
- 用語は「**種類**」で統一する（「箱」は図の説明の中だけ:「図の箱 = データの種類」）。
  直しのラベルも「1 つの種類を 2 つに分ける」
- ④の表は横スクロールさせない（意味の長文は折り返す。値は 1 行に省略表示）
- 「形が違うとき（直す）」= 切り替え式の 4 カード: 名前を変える／1 つの箱を 2 つに分ける
  （名前が先 → 移す項目。旧 D4「同じ ID で種類を足す」を吸収）／項目を移す（このとき
  だけ帰属 UI を出す）／ID を候補から選び直す（仮のときの導線）
- 詳細モード（workbench）は現行エディタを維持。かんたん層だけの転換

### D5 骨格組み立ての決定論化 — round-0 の LLM 呼び出しを廃止する

かんたんモードの骨格は「③④の答え + 検査」から**組み立てる**ものになり、LLM の提案では
なくなる。実測の失敗（行だけの 1 種類・双子・組成の見落とし）は骨格提案の確率性由来で、
出どころごと消える。LLM に残る仕事: ③の意味の下書き・種類名の下書き・任意の相談
（D3 提案）。kind-splitting で入れた決定論（twinKindNames / fold_twin_kinds /
missing_card_kind / 帰属の裁定）は、人の編集に対する**保険**としてそのまま残る。

## 3. 非目標

- 詳細モードの改廃（現行エディタ維持）
- ID の作り方（IRI テンプレート）の AI 提案（現行どおり非提案）
- kind-splitting D1〜D4 機構の削除（⑤の直し・保険として残置）
- 合成のファイル由来 ID（D3 の将来オプション。今回は仮置き + 明示）

## 4. 段構成

かんたんモードは 6 → 7 段: 1 入れる / 2 AI が読む / 3 項目の意味 / **4 外とのつながり** /
**5 できた形をたしかめる** / 6 ためす / 7 公開する。manual・照合テスト・スクリーンショットを
同じ PR 群で追随させる。

## 5. 検証

- モック（実データ・実 ShapeGraph）で確認済み: ☑ ↔ 箱の連動／名指し 1 問による ID 導出／
  ゼロ ☑ の仮 ⚠／箱を分ける（名前が先）／ID 選び直し
- 実装の受け入れ: XRD 参考カードで③④に答えるだけで カード + ピーク + 受け口が組み上がり、
  **No が ID になるのは④で選んだときだけ**であること。ゼロ ☑ で仮 ⚠ が出ること。
  組み立て結果が既存の annotate 検査（一意性・scope・K7）を全部通ること
- 文言の効き（「化学式のような決まった書き方」で組成が選ばれるか）は実利用者の一周で測る

## 6. 実装の分割（それぞれ独立に PR できる）

1. **server**: ③④の答えから骨格を組み立てる決定論 API（`skeleton_from_judgments`）+
   仮フラグの annotation
2. **ui**: ④「外とのつながり」新画面（S2 q2 の吸収を含む）
3. **ui**: ⑤の書き換え（グラフ主役化・直し 4 カード）
4. **docs**: 段番号・manual・スクリーンショットの追随
